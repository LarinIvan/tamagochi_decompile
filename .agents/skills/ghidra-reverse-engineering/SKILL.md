# Ghidra Reverse Engineering Skill

Данный скилл описывает методику и пошаговый процесс реверс-инжиниринга исполняемых файлов и прошивок с помощью **Ghidra** и **Ghidra MCP Server**.

## 1. Подключение и архитектура

Ghidra MCP работает через два компонента:
1. **Ghidra Plugin (Java)**: работает внутри Ghidra (GUI или headless), слушает HTTP API на `http://127.0.0.1:8089`.
2. **MCP Bridge (Python)**: CLI/Stdio сервер `bridge-mcp-ghidra`, транслирующий MCP-вызовы агента в команды Ghidra.

### Проверка соединения
```bash
curl http://127.0.0.1:8089/check_connection
# Ожидаемый ответ: {"status": "ok", "server_kind": "gui", "version": "7.0.0"}
```

## 2. Группы инструментов (Lazy Loading)

Сервер предоставляет более 200 инструментов. Для экономии контекста по умолчанию загружаются базовые группы: `listing`, `function`, `program`.
Для вызова специализированных инструментов используйте:
- `search_tools(query="...")` — поиск доступного инструмента по ключевым словам.
- `load_tool_group(group="...")` — динамическая подгрузка группы (например, `decompiler`, `datatype`, `xref`, `pcode`, `comments`, `emulator`).

## 3. Рабочий процесс анализа функций

При анализе неисследованного бинарного файла следуйте методологии:

1. **Приоритизация**:
   - Находите функции с наибольшим количеством перекрёстных ссылок (`xrefs`).
   - Сосредоточьтесь на функциях с префиксом по умолчанию `FUN_` или `thunk_FUN_`.

2. **Изучение контекста и декомпиляция**:
   - Вызовите декомпилятор для целевой функции.
   - Проанализируйте входящие параметры, вызовы других функций (`callees`) и глобальные переменные.

3. **Соглашения по именованию**:
   - **Функции**: `PascalCase` с выражением действия, отражающим назначение (например, `ProcessInputBuffer`, `RenderScreenState`).
   - **Переменные и параметры**: `camelCase`, описывающие смысл данных (например, `packetLength`, `targetAddress`). Избегайте артефактов `local_` и `param_`.
   - **Метки переходов (Jump Labels)**: `snake_case`, описывающие ветвление (например, `loop_start`, `error_handler`, `validation_failed`).

4. **Типизация и структуры**:
   - Уточняйте типы возвращаемых значений (`void`, `bool`, `uint32_t`, указатели на структуры).
   - Создавайте структуры данных при обращении по смещениям к буферам или объектам (`StructField`).

5. **Документирование**:
   - Добавляйте Plate-комментарии к функциям с описанием их назначения, параметров и побочных эффектов.
